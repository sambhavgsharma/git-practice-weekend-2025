1.  What’s your reason for participating?
State your purpose (learn something, get help, see a bug get fixed). Higher clarity of purpose results in productivity.

2.  Be Respectful
Always show respect, thank and congratulate. Always use neutral language and don’t assume background or knowledge.

3.  Fix Things 
Real fix first, no matter how much you want to change a small things of the style, don’t waste time fixing things based on personal preferences. Referring to the contributing guide.
These tiny fixes are discouraged

4.  Read First
Always read the contributing.md or readme.md before opening issues or asking questions.

5.  Ask In The Right Place
Use the proper location (not issues) for general inquiries.

6.  Stay Focused
Only one issue per issue and one issue at a time per PR. Stay on topic and ask specific questions.

7.  Accept Decisions
contributing decisions are made by core contributors. You can fight against it but keep the disagreement mutually agreed upon.

8.  Be Patient
Contributors are doing this voluntarily. Be patient, don't use your time in a bad way to get something answered by given statements, and let us know if you are going to be late.

Other Points
1. Observe coding standards and provide clear commit messages.
2. Test all contributions and create unit tests if required.
3. Provide positive feedback and present solutions.
4. Consider system resources to avoid wasting capacity.
